# 第一层高内存代码审查 — 2026-10-24

结论：未发现第一层特有的算术错误证据，但 fast 卷积路径存在明确的中间量膨胀、stride 重排重复计算和分配器压力。第一层形状和较长模数链放大了这些问题。以下没有修改生产算法、线程数、密钥方案或已完成的实验结果。

## 第一层与第二层的规模差异

以已完成的 ring=16384、slots=2048、30/40、depth=40、80×80 为例：

| 项目 | 第一层 | 第二层 |
|---|---:|---:|
| 输入特征宽度 | 224 | 112 |
| 卷积核 / stride | 7×7 / 2 | 3×3 / 2 |
| 输出通道数 | 64 | 64 |
| 受影响输出行/列 | 43 / 43 | 23 / 23 |
| 输入剩余 RNS 素数数目 | 41 | 29 |
| 输出密文数量（ReLU 后布局） | 172 | 46 |
| 通道累加器容量量级（GiB） | 27.5 | 10.4 |
| stride 压缩掩码乘法次数 | 118336 | 33856 |
| ReLU 秒/密文 | 6.825 | 6.852 |

累加器容量是按每个密文包含两个多项式、N=16384、每个 RNS 系数 8 字节估算的量级，不是分项实测；自动缩放可能改变临时密文层级。第二层的 ReLU 每密文成本与第一层相近，总耗时差异主要来自密文数量。

## 具体实现问题

1. **每个并发通道保留所有受影响行的累加器。** `src/cnn/sparse_conv2d.cpp:613–630` 中，64 个通道任务各有 `accum(rows)`。第一层最多约 2752 个通道累加密文同时存活，远多于最后打包输出的 172 个密文。这不是稀疏输入本身要求的最低内存，而是当前计算组织方式的代价。

2. **stride=2 用逐列掩码乘法和旋转压缩，每个通道/每行都重复。** `src/cnn/sparse_conv2d.cpp:642–652` 为每个输出列构造临时密文，再旋转相加。第一层有 64×43×43=118336 次掩码乘法，并有接近相同数量的旋转。后续 stride=1 分支只需一次 selector 乘法。这解释了第一层时间和内存分配压力特别大；它不等于计算结果错误。按通道块重排需要重新设计布局，不能简单把代码移到归并之后。

3. **热点循环大量使用返回新密文的 EvalAdd。** `src/cnn/sparse_conv2d.cpp:630,650,663` 会反复申请、释放大型 RNS 缓冲区。确认目标对象独占后，可以考虑原位累加，减少复制和分配；不能机械地把递归 reduce 内部全部换成原位操作，因为递归分支可能仍引用原始密文。

4. **第一层通道归约包含空通道。** 当前 `per=floor(2048/224)=9`，实际输入只有 3 个通道，但 `reduce(accum[row], per)` 仍按 9 通道归约。系数掩码让额外通道为零，因此这通常是冗余计算而非正确性错误。第一层归约可考虑按实际占用通道数 3 进行，理论上每个通道/输出行能少两次旋转，合计约 5504 次；修改后仍需完整正确性与性能检查。

5. **初始输入与 ReLU 的生命周期可进一步缩短，但不是几十 GiB 的主因。** `InitResNet18` 将 `encrypted,input` 按左值传给按值接收的 `Network::predict_P`，外层原始密文引用一直保留；第一层初始 80 个密文约 0.8 GiB。ReLU 在处理过程中保留全部输入，并逐步积累输出。它们可考虑移动所有权或消费后及时释放，但不能把约 40 GiB 的差异全部归给这两处。

## 分配器保留机制的小测验证

使用独立 `conv_memory_bench baseline 0 allocator` 进程，保持直接旋转、96 个全局线程、无通道限流。配置为 ring32768、depth40、30/40、digits6、2048 slots 的合成 Conv+BN；它不是原始 80×80 全模型复跑。

| 时点 | RSS GiB | 堆内已用 GiB | 堆内空闲 GiB |
|---|---:|---:|---:|
| 生成密钥后 | 11.17 | 7.23 | 3.93 |
| 卷积 forward 返回后 | 16.81 | 7.33 | 9.47 |
| 验证完成、诊断回收前 | 13.36 | 7.33 | 6.02 |
| 仅执行诊断 malloc_trim 后 | 7.35 | 7.33 | 6.02 |

另有约 1 MiB 独立 mmap 分配。`mallinfo2` 的“堆内空闲”是分配器地址空间统计，空闲块被 madvise 归还物理页后仍可留在 arena 中，因此 trim 后 free 数值基本不变，而 RSS 显著下降是合理的。

明文参考最大绝对误差约 8.34e-6，检查通过。诊断回收发生在计时和正确性检查之后，未被加入生产代码，也没有把它宣称为不增加时延的优化。该小测证明分配器滞留机制可以被当前代码复现，不能据此精确分摊原始 73 GiB 的全部组成。

建议优先减少重复的 stride 重排、在安全所有权边界使用原位累加、去掉空通道归约，并为后续小测记录各阶段 mallinfo2 used/free。保持线程数与直接旋转不变；每项改变都应分别检查耗时和正确性，不再默认用降低并行或额外旋转换内存。
