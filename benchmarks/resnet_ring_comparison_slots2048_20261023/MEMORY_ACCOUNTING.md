# 内存统计口径更正

此前报告的 `peak_gib`、GNU time `Maximum resident set size` 和逐层 CSV 的 `peak_mib` 均为**同一实验进程从启动以来的最高 RSS**。该进程同时执行密钥生成、客户端输入加密、模型准备、同态推理和明文参考校验。这些值不能作为“云端推理峰值内存”引用，也不能通过减去一个估计的密钥生成峰值得到云端峰值。

应区分：

| 阶段或对象 | 云端在线推理内存是否计入 |
|---|---|
| 客户端秘密密钥生成、评估密钥生成的临时工作区 | 不计入 |
| 客户端输入编码、加密的临时工作区 | 不计入 |
| 云端运行时必须保留的评估/旋转/方案切换密钥 | 计入 |
| 云端必须保留的模型、预计算矩阵、加密输入 | 计入 |
| 推理中间密文、输出密文和算子工作区 | 计入 |
| 为实验校验额外保留的明文参考张量及参考计算工作区 | 不应计入；当前同进程 RSS 尚未完全剥离它们 |

云端冷启动（加载模型、密钥和生成服务器预计算）应另列；是否计入在线请求延迟和峰值取决于部署模型，不能与客户端 KeyGen 混为一谈。

当前补充的 5 秒 RSS 采样和日志阶段标记，可以报告**已观察到的推理阶段 RSS 均值、中位数及采样最大值**。它没有能力回溯已结束阶段，也不是隔离客户端/校验进程后的严格服务器内存测量。70×70 的采样从运行中途开始；80×80 从进程启动附近采样，仍受阶段推断和采样间隔限制。客户端生成阶段的 VmHWM 不再作为推理采样最大值使用。

严格测量应在客户端准备完毕后，将密文和必要评估材料交给独立服务器进程；服务器从其定义的推理边界记录 RSS，验证在另一个进程中完成。当前批量实验不被打断或替换，其原始测量保留，但统一按整进程实验峰值解释。
