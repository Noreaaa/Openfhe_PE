# Original main-branch fully encrypted baseline reproduction

Updated UTC: 2026-10-25T13:55:37.288956+00:00

## Provenance and exact scope

Repository main branch at commit 08e56ef. The original src/main.cpp baseline_test entry, Conv2d_C and Relu_appx are executed, without the feature-branch convolution adapters or normalized polynomials. The main-branch worktree remains clean. The sole build compatibility addition is the missing conv2d_l.hpp declaration header copied into an external include directory from the feature branch; no classes from that header are instantiated by this entry. Build/output files live outside the repository.

Each process runs one fully encrypted synthetic convolution followed by the original polynomial activation + EvalBootstrap call. Input/output channel counts are 64, 128, 256 or 512 and input widths 56, 28, 14 or 7. Original Conv2d_C does not implement padding: outputs are 54, 26, 12 and 5, not the same-padding shapes of the previous adapted baseline. BN is not part of this original baseline_test entry. Inputs and filters are generated by the original deterministic rand()/9 routines, not by ResNet inference or trained convolution weights. The layer index labels identify representative shapes only.

## Original parameters and initialization

Ring 16384 or 32768, slots=N/2, scaling/first moduli 30/40 bits, HYBRID numLargeDigits=3. Depth is computed as GetBootstrapDepth({3,3}, UNIFORM_TERNARY)+3 (23 in this installed library). Actual bootstrap setup uses budget {4,3}, correction factor 10. The inconsistency between the two budgets is preserved. Threads: 96, nested teams disabled via environment.

The original code always generates bootstrap keys and also sets USE_SS=true unconditionally. Consequently approximation runs also initialize FHEW, its bootstrap key, and CKKS/FHEW scheme-switching keys, even though the baseline activation is Relu_appx. This extra resident setup is deliberately preserved; it is a concrete difference from the earlier approximation-only adapters and a possible explanation for historical memory near 90 GiB.

Original Relu_appx evaluates its unnormalized degree-6 polynomial and calls EvalBootstrap inside the channel-parallel loop. The original call is not forced to start from depleted ciphertexts; OpenFHE can return the input if the refresh does not improve the tower count. Thus an EvalBootstrap call is not proof that levels were refreshed. No FHEW activation is executed by baseline_test.

## Measurement limits

GNU time measures whole-process wall time and lifetime peak RSS. Operator timings are parsed from the original model's Layer 0/1 messages; activation includes both polynomial and bootstrap call and cannot be split without changing the entry. Phase labels in rss.csv are inferred from log milestones with 0.5-second sampling, not instrumentation inside old code. Prediction time includes the original model's final decryption/printing. Whole-process wall also includes data/weight loading, synthetic generation and original validation/printing. No allocator trimming. A host MemAvailable guard stops a case below 12 GiB; failures are retained and not counted as successful runs.

The original final check compares polynomial output against exact ReLU, so its reported average relative loss is a model approximation metric, not a cryptographic arithmetic check. Zero exit status alone does not establish acceptable activation accuracy.
